Todo modelo de machine learning puede caer en uno de tres estados: memorizar los datos de entrenamiento sin generalizar, no aprender la señal suficiente, o encontrar el equilibrio entre ambos. Diagnosticar el estado del modelo es tan importante como entrenarlo.

01 — Los tres casos

Los tres escenarios de ajuste

El diagnostico se hace comparando el AUC-ROC en entrenamiento con el AUC-ROC en prueba. La diferencia entre ambos, junto con el nivel absoluto de las metricas, revela el estado del modelo.

Caso 1 — Overfitting (sobreajuste)
AUC Train: 0.95
AUC Test: 0.63
Diferencia: 0.32 <-- ALARMA

El modelo memorizo los 440K viajes del train, incluyendo el ruido. Un taxi desde JFK que pago en efectivo a las 3am — caso atipico — se aprende como regla en lugar de tratarse como excepcion.

Causa tipica en Boosting:

max_depth muy alto (8-12)
n_estimators muy alto (500+)
learning_rate alto (0.3+)
sin regularizacion (gamma=0)
sin subsampling

El modelo aprende hasta el ultimo detalle del train, incluyendo errores de GPS y tarifas mal registradas. Al ver datos nuevos, ese conocimiento no sirve.

Caso 2 — Buen Ajuste
AUC Train: 0.72
AUC Test: 0.70
Diferencia: 0.02 <-- IDEAL

El modelo aprendio patrones reales: viajes desde zonas de alta propension a tarjeta, tarifas altas, distancias largas. Estos patrones se replican en datos nuevos porque son reales, no ruido.

Configuracion tipica:

max_depth = 4-6
learning_rate = 0.05
n_estimators = 200-300
subsample = 0.8
gamma = 0.1 (XGBoost)

El modelo generaliza: lo que aprende en el train se mantiene en el test porque captura la estructura real del fenomeno, no los accidentes de la muestra.

Caso 3 — Underfitting (subajuste)
AUC Train: 0.61
AUC Test: 0.59
Diferencia: 0.02 <-- pequeña
Pero ambos son bajos <-- PROBLEMA

El modelo no logra capturar la señal. Un arbol muy simple solo aprende "si fare_amount mayor a 12 entonces Tarjeta", perdiendo toda la informacion de zona, distancia e interacciones.

Causa tipica:

max_depth muy bajo (1-2)
n_estimators muy bajo (<50)
learning_rate muy bajo (0.001)
regularizacion excesiva
features insuficientes

El underfitting es opuesto al overfitting pero igualmente problematico. El modelo no sirve ni para el train ni para el test. Es demasiado ingenuo para el problema.

02 — Deteccion

Como detectarlos

La herramienta principal es la curva de aprendizaje: AUC-ROC en train y test a lo largo de las iteraciones del modelo. El patron de las dos curvas revela el diagnostico.

Overfitting

Train: sube y sigue subiendo
Test: sube y luego baja
Las curvas se separan

Buen Ajuste

Train: sube y se estabiliza
Test: sube y se estabiliza
Las curvas convergen

Underfitting

Train: sube muy poco
Test: sube muy poco
Ambas curvas quedan bajas

Reglas de diagnostico numericas

CondicionDiagnosticoGravedad
diff mayor a 0.10Overfitting severoCritico — el modelo no sirve en produccion
diff mayor a 0.05Overfitting moderadoRequiere correccion antes de usar
diff menor a 0.02 y AUC test mayor a 0.70Buen ajusteModelo listo para produccion
diff menor a 0.02 y AUC test menor a 0.65UnderfittingModelo demasiado simple
diff entre 0.02 y 0.05Zona grisAceptable segun el contexto

En NYC Taxi con 7 features sin leakage: un AUC test de 0.63-0.73 es razonable. El problema no es el modelo, son las variables disponibles. Las zonas tienen poder predictivo limitado cuando no incluimos tip_amount.

La trampa de la accuracy: con 84/16 de desbalance, un modelo que predice siempre Tarjeta tiene accuracy de 0.84 pero AUC-ROC de 0.50. Siempre usar AUC-ROC para el diagnostico de ajuste, no accuracy.

04 — Soluciones

Que hacer segun el diagnostico

Cada tipo de desajuste tiene un conjunto de acciones correctivas especificas sobre los hiperparametros del modelo.

Si hay Overfitting — reducir complejidad
HiperparametroAccion
max_depthReducir (ej: de 8 a 4)
n_estimatorsReducir o usar early stopping
learning_rateReducir (ej: de 0.1 a 0.05)
subsampleReducir (ej: de 1.0 a 0.8)
colsample_bytreeReducir (ej: de 1.0 a 0.7)
gammaAumentar (ej: de 0 a 0.1)
reg_alphaAumentar regularizacion L1
reg_lambdaAumentar regularizacion L2
min_samples_leafAumentar (GBM)

Early stopping en XGBoost es la solucion mas elegante: el modelo se detiene automaticamente cuando el AUC en test deja de mejorar, evitando el overfitting sin adivinar n_estimators.

Si hay Underfitting — aumentar complejidad
HiperparametroAccion
max_depthAumentar (ej: de 2 a 5)
n_estimatorsAumentar (ej: de 50 a 200)
learning_rateAjustar — ni muy alto ni muy bajo
gammaReducir o poner en 0
reg_alphaReducir regularizacion
min_samples_leafReducir (GBM)
FeaturesAgregar variables mas informativas
InteraccionesCrear features combinadas

En NYC Taxi con 7 features sin leakage, el underfitting puede ser estructural: las variables disponibles tienen poder predictivo limitado. Agregar hora del dia o dia de la semana puede ayudar.

El trade-off fundamental — curva de complejidad

Zona izquierda: modelo simple. Tanto train como test tienen AUC bajo. Underfitting.

Zona central: complejidad optima. Train y test son similares y altos. Buen ajuste.

Zona derecha: modelo complejo. Train muy alto, test baja. Overfitting.

05 — Codigo

Codigo de diagnostico

Codigo listo para Jupyter. Asume ada, gbm, model_xgb, X_train, X_test, y_train, y_test del pipeline de NYC Taxi.

# ═══════════════════════════════════════════════════════════════════ # DIAGNOSTICO DE OVERFITTING / UNDERFITTING — Modelos Boosting # ═══════════════════════════════════════════════════════════════════ from sklearn.metrics import roc_auc_score modelos = { "AdaBoost" : ada, "Gradient Boosting": gbm, "XGBoost" : model_xgb, } print("=" * 65) print(f"{'Modelo':<22} {'AUC Train':>10} {'AUC Test':>10} {'Diff':>8} {'Diagnostico':>14}") print("=" * 65) for nombre, modelo in modelos.items(): y_proba_train = modelo.predict_proba(X_train)[:, 1] auc_train = roc_auc_score(y_train, y_proba_train) y_proba_test = modelo.predict_proba(X_test)[:, 1] auc_test = roc_auc_score(y_test, y_proba_test) diff = auc_train - auc_test if diff > 0.10: diag = "OVERFIT SEVERO" elif diff > 0.05: diag = "OVERFIT MODERADO" elif auc_test < 0.65: diag = "UNDERFITTING" elif diff <= 0.02: diag = "BUEN AJUSTE" else: diag = "ACEPTABLE" print(f"{nombre:<22} {auc_train:>10.4f} {auc_test:>10.4f} {diff:>8.4f} {diag:>14}") print("=" * 65) # ── Curva de aprendizaje GBM (por iteracion) ────────────────── import matplotlib.pyplot as plt aucs_train, aucs_test = [], [] for proba_train, proba_test in zip( gbm.staged_predict_proba(X_train), gbm.staged_predict_proba(X_test) ): aucs_train.append(roc_auc_score(y_train, proba_train[:, 1])) aucs_test.append(roc_auc_score(y_test, proba_test[:, 1])) fig, ax = plt.subplots(figsize=(8, 4)) ax.plot(aucs_train, label="Train", color="#2d6a4f", lw=2) ax.plot(aucs_test, label="Test", color="#1a3a6b", lw=2) ax.fill_between(range(len(aucs_train)), aucs_train, aucs_test, alpha=0.12, color="#c0392b", label="Brecha") ax.set_xlabel("Iteracion (n_estimators)") ax.set_ylabel("AUC-ROC") ax.set_title("Curva de aprendizaje — GBM — NYC Taxi") ax.legend() plt.tight_layout() plt.show()

staged_predict_proba es un metodo exclusivo de GBM en sklearn. Devuelve las predicciones de probabilidad despues de cada arbol, permitiendo ver como evolucionan train y test a lo largo del entrenamiento. XGBoost tiene el equivalente via eval_set en el fit.
