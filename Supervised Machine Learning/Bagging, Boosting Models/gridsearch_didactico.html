Dos estrategias para encontrar los mejores hiperparametros de un modelo. Una es exhaustiva y garantiza el optimo dentro de la grilla. La otra es aleatoria y es la unica viable cuando el espacio de busqueda es grande.

GridSearchCV

01 — GridSearch

GridSearch — busqueda exhaustiva

Evalua sistematicamente todas las combinaciones posibles de los valores de hiperparametros que defines. Como una cuadricula: visita cada interseccion.

Como funciona

Con 2 hiperparametros y 3 valores cada uno:

max_depth = [3, 4, 6]
learning_rate = [0.01, 0.05, 0.1]

Combinaciones evaluadas:
(3, 0.01) (3, 0.05) (3, 0.10)
(4, 0.01) (4, 0.05) (4, 0.10)
(6, 0.01) (6, 0.05) (6, 0.10)

Total: 3 x 3 = 9 combinaciones
Con cv=3: 9 x 3 = 27 entrenamientos

Cuadricula interactiva

Haz clic en cualquier celda para ver que combinacion evalua GridSearch.

El problema del crecimiento exponencial

2 parametros x 3 valores:
3^2 = 9 combinaciones

4 parametros x 3 valores:
3^4 = 81 combinaciones

6 parametros x 3 valores:
3^6 = 729 combinaciones

8 parametros x 3 valores (XGBoost):
3^8 = 6,561 combinaciones
x 3 folds = 19,683 entrenamientos
x 2 min = ~27 dias de computo

Cuando usar GridSearch: cuando tienes 3 o menos hiperparametros y el dataset es pequeno. Para XGBoost con NYC Taxi es completamente inviable.

Ventajas y limitaciones

GridSearch
GarantiaEncuentra el optimo dentro de la grilla definida
ReproducibilidadSiempre da el mismo resultado
CostoCrece exponencialmente con parametros
EscalabilidadInviable con mas de 4-5 hiperparametros
SesgoSolo evalua los valores que defines en la grilla
02 — RandomizedSearch

RandomizedSearch — busqueda aleatoria

En lugar de evaluar todas las combinaciones, sortea N combinaciones aleatorias del espacio de busqueda. Controlas el presupuesto computacional directamente con n_iter.

Como funciona

Con los mismos 2 hiperparametros pero n_iter=5:

max_depth = [3, 4, 6]
learning_rate = [0.01, 0.05, 0.1]

Combinaciones sorteadas (n_iter=5):
(4, 0.05) <-- sorteada
(3, 0.10) <-- sorteada
(6, 0.01) <-- sorteada
(4, 0.01) <-- sorteada
(3, 0.05) <-- sorteada

Total: 5 combinaciones
Con cv=3: 5 x 3 = 15 entrenamientos

El argumento de Bergstra y Bengio (2012)

En la practica los hiperparametros NO son igualmente importantes. learning_rate y max_depth dominan el resultado de XGBoost. reg_alpha y reg_lambda tienen efecto menor.

GridSearch desperdicia el mismo esfuerzo en parametros importantes y no importantes. RandomizedSearch, al muestrear el espacio completo, explora MAS valores distintos de los parametros importantes por el mismo costo.

La probabilidad de exito

Si el "valle optimo" ocupa el 5% del espacio:

P(encontrarlo en 1 intento) = 0.05
P(encontrarlo en 20 intentos) = 1-(0.95^20) = 0.64
P(encontrarlo en 50 intentos) = 1-(0.95^50) = 0.92

Con n_iter=20 tienes 64% de probabilidad de caer en una region buena al menos una vez.

Ventajas y limitaciones

RandomizedSearch
CostoControlado exactamente con n_iter
EscalabilidadFunciona con cualquier numero de parametros
Distribucion continuaPuede muestrear de rangos continuos, no solo valores discretos
GarantiaNo garantiza encontrar el optimo absoluto
ReproducibilidadRequiere fijar random_state

Ventaja con distribuciones continuas

RandomizedSearch puede muestrear de distribuciones, no solo listas:

from scipy.stats import uniform, randint

parametros = {
  'learning_rate': uniform(0.01, 0.29),
  'max_depth' : randint(3, 9),
  'subsample' : uniform(0.6, 0.4),
}

# Puede explorar 0.0312, 0.0847, 0.1923...
# GridSearch solo exploraria 0.01, 0.05, 0.1

Para XGBoost con NYC Taxi: n_iter=20 con cv=3 da 60 entrenamientos. A ~2 minutos por entrenamiento son ~2 horas. Manejable en tu Mac con n_jobs=-1.

03 — Intuicion Geometrica

El espacio de hiperparametros

Imagina el espacio de hiperparametros como un mapa topografico. Las zonas bajas (valles) representan buenas combinaciones. Las zonas altas (montanas) representan malas combinaciones.

GridSearch — cuadricula uniforme

Los puntos negros son las combinaciones evaluadas. La cuadricula cubre todo el espacio pero puede perderse valores intermedios optimos.

RandomizedSearch — muestreo disperso

Los puntos azules son las combinaciones sorteadas. Misma cantidad de evaluaciones pero mayor cobertura del espacio.

La intuicion clave — parametros de distinta importancia

En XGBoost para NYC Taxi:

MUY importante learning_rate — controla cuanto aprende cada arbol

MUY importante max_depth — controla la complejidad

Moderado subsample — reduce overfitting

Moderado colsample_bytree — reduce overfitting

Menor efecto reg_alpha — regularizacion L1

Menor efecto reg_lambda — regularizacion L2

GridSearch: gasta el mismo numero de evaluaciones en reg_alpha (poco importante) que en learning_rate (muy importante).

RandomizedSearch: al muestrear aleatoriamente, cada parametro importante recibe muchos valores distintos. Con 20 iteraciones exploras 20 valores distintos de learning_rate en lugar de solo 3.

En tu notebook NYC Taxi: usaste GridSearchCV para CART (48 combinaciones, manejable). Para Random Forest usaste RandomizedSearchCV con n_iter=20. Para XGBoost con 8 parametros, RandomizedSearchCV con n_iter=20-50 es la unica opcion practica.

Alternativas avanzadas: Optuna y Hyperopt implementan busqueda bayesiana — aprenden de evaluaciones anteriores para dirigirse hacia regiones prometedoras. Son mas eficientes que RandomizedSearch para presupuestos muy pequenos (n_iter < 20).

06 — Codigo

Codigo completo

Implementacion lista para Jupyter con XGBoost y NYC Taxi. Asume X_train, y_train, X_test, y_test del pipeline anterior.

# GridSearchCV — viable solo con pocos parametros # Ejemplo con CART (48 combinaciones, manejable) from sklearn.model_selection import GridSearchCV from sklearn.tree import DecisionTreeClassifier parametros = { 'max_depth' : [4, 6, 8, 12], 'min_samples_split': [20, 100, 500], 'min_samples_leaf' : [10, 50], 'criterion' : ['gini', 'entropy'], } # 4 x 3 x 2 x 2 = 48 combinaciones x 5 folds = 240 entrenamientos grid = GridSearchCV( estimator=DecisionTreeClassifier(random_state=42), param_grid=parametros, scoring='roc_auc', cv=5, n_jobs=-1, verbose=1 ) grid.fit(X_train, y_train) print("Mejores parametros:", grid.best_params_) print(f"Mejor AUC-ROC (CV): {grid.best_score_:.4f}")
# RandomizedSearchCV — para XGBoost con NYC Taxi from sklearn.model_selection import RandomizedSearchCV import xgboost as xgb neg = (y_train == 0).sum() pos = (y_train == 1).sum() parametros_xgb = { 'n_estimators' : [200, 300, 500], 'learning_rate' : [0.01, 0.05, 0.1], 'max_depth' : [3, 4, 6], 'subsample' : [0.7, 0.8, 1.0], 'colsample_bytree': [0.6, 0.8, 1.0], 'gamma' : [0, 0.1, 0.5], 'reg_alpha' : [0, 0.1, 0.5], 'reg_lambda' : [0.5, 1.0, 2.0], } # 3^8 = 6,561 combinaciones con GridSearch # Con RandomizedSearch: solo 20 combinaciones xgb_base = xgb.XGBClassifier( scale_pos_weight=neg/pos, eval_metric='auc', random_state=42, verbosity=0 ) random_search = RandomizedSearchCV( estimator=xgb_base, param_distributions=parametros_xgb, n_iter=20, scoring='roc_auc', cv=3, n_jobs=-1, verbose=1, random_state=42 ) random_search.fit(X_train, y_train) print("Mejores parametros:", random_search.best_params_) print(f"Mejor AUC-ROC (CV): {random_search.best_score_:.4f}") xgb_final = random_search.best_estimator_ y_pred_xgb = xgb_final.predict(X_test) y_proba_xgb = xgb_final.predict_proba(X_test)[:, 1]
# RandomizedSearchCV con distribuciones continuas (scipy.stats) # Explora el espacio de forma mas rica que con listas discretas from sklearn.model_selection import RandomizedSearchCV from scipy.stats import uniform, randint, loguniform import xgboost as xgb neg = (y_train == 0).sum() pos = (y_train == 1).sum() parametros_xgb = { 'n_estimators' : randint(100, 600), 'learning_rate' : loguniform(0.005, 0.3), # escala logaritmica 'max_depth' : randint(3, 8), 'subsample' : uniform(0.6, 0.4), # uniforme en [0.6, 1.0] 'colsample_bytree': uniform(0.5, 0.5), # uniforme en [0.5, 1.0] 'gamma' : uniform(0, 1), 'reg_alpha' : loguniform(1e-4, 1), 'reg_lambda' : loguniform(0.1, 10), } xgb_base = xgb.XGBClassifier( scale_pos_weight=neg/pos, eval_metric='auc', random_state=42, verbosity=0 ) random_search = RandomizedSearchCV( estimator=xgb_base, param_distributions=parametros_xgb, n_iter=50, # mas iteraciones = mejor resultado scoring='roc_auc', cv=3, n_jobs=-1, verbose=1, random_state=42 ) random_search.fit(X_train, y_train) print("Mejores parametros:", random_search.best_params_) print(f"Mejor AUC-ROC (CV): {random_search.best_score_:.4f}")

loguniform vs uniform: para learning_rate conviene muestrear en escala logaritmica porque la diferencia entre 0.001 y 0.01 es tan importante como entre 0.01 y 0.1. Con uniform casi nunca se explorarian valores pequenos.
