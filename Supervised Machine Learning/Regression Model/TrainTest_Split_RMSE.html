01 — El Problema

El modelo que hace trampa

Imagina que usas los mismos datos para entrenar el modelo y para medir su error. El resultado parece excelente — pero es una ilusion.

A

El modelo memoriza

Si evaluas en los mismos datos con los que entrenas, el modelo aprende de memoria cada observacion — incluyendo el ruido aleatorio. Sobre esos datos parece perfecto.

B

Las metricas mienten

El RMSE calculado sobre los datos de entrenamiento es optimista por construccion. No dice nada sobre como funcionara el modelo con datos nuevos.

C

La solucion: datos nunca vistos

Separar un conjunto de test que el modelo jamas ve durante el entrenamiento. El error sobre ese conjunto es una estimacion honesta del error real en produccion.

Regla de oro: el modelo nunca debe ver los datos de test antes de la evaluacion final. Si los ve, la evaluacion pierde todo valor cientifico.

La analogia del examen

Mala practica

Memorizar las respuestas

El estudiante estudia con el examen resuelto en mano. Obtiene 10/10 en ese examen, pero falla en cualquier pregunta nueva. No aprendio — memorizo.

Train error: 0.00 Test error: alto
Buena practica

Entender el concepto

El estudiante practica con ejercicios distintos al examen final. Su calificacion refleja comprension genuina, no memoria de los ejemplos vistos.

Train error: bajo Test error: bajo

Los datos de train son los ejercicios de practica. Los datos de test son el examen final sorpresa. El modelo solo aprende de los primeros — jamas de los segundos.

02 — Sobreajuste

Overfitting — el enemigo silencioso

Un modelo puede ajustarse perfectamente a los datos de entrenamiento y fracasar completamente con datos nuevos. Ese fenomeno se denomina sobreajuste.

Los tres escenarios posibles

Escenario A — Sobreajuste (Overfitting)

Modelo demasiado complejo. Aprende el ruido especifico de los datos de entrenamiento. El error en train es casi cero; en test, es catastrofico.

RMSE Train: 1.2 RMSE Test: 8.7
Escenario B — Buen Ajuste

Modelo de complejidad apropiada. Captura el patron real sin aprender el ruido. Los errores en train y test son similares entre si.

RMSE Train: 3.1 RMSE Test: 3.4
Escenario C — Subajuste (Underfitting)

Modelo demasiado simple. No logra capturar el patron subyacente. Mal desempeno tanto en train como en test.

RMSE Train: 9.2 RMSE Test: 9.8

El proceso paso a paso

1

Aleatorizar. Mezclar todas las observaciones aleatoriamente. Usar una semilla fija garantiza reproducibilidad.

2

Separar. Asignar el X% inicial a train y el resto a test. Nunca mezclar los conjuntos despues.

3

Entrenar. Ajustar el modelo exclusivamente con los datos de train. El test permanece intocable.

4

Evaluar. Calcular las metricas sobre el conjunto de test. Este numero es el que se reporta.

04 — Semilla y Reproducibilidad

test_size y random_state

La particion train/test es aleatoria. Sin semilla fija, dos estudiantes que corran el mismo codigo obtendran particiones distintas — y en consecuencia estimaciones y pronosticos distintos.

Los dos parametros clave

X_train, X_test, y_train, y_test = train_test_split(
    X, y,
    test_size=0.20,  # 20% test, 80% train
    random_state=42   # semilla fija
)
1

test_size = 0.20

Define el porcentaje de la muestra que va a test. Con test_size=0.20 y n=30 observaciones: 6 van a test y 24 a train.

2

random_state = 42

Es la semilla (SEED) que controla la aleatoriedad de la particion. El numero puede ser cualquiera — lo importante es fijarlo para que todos obtengan la misma division.

Sin semilla: si corres el codigo varias veces, o si otro estudiante lo corre en su maquina, la particion cambia. Cambia el train, cambia el modelo estimado y cambian los pronosticos. La semilla garantiza reproducibilidad.

04 — Generalizacion

El objetivo real: generalizar

Un modelo util no es el que mejor se ajusta a los datos que ya tiene — es el que mejor predice datos que aun no ha visto. Esa propiedad se llama generalizacion.

Que es la generalizacion

La capacidad de generalizacion es la habilidad del modelo de producir predicciones precisas sobre observaciones nuevas, no sobre las que lo entrenaron. Es la diferencia entre un modelo util y uno que solo funciona en el laboratorio.

Generalizacion alta: el modelo aprendio el patron subyacente. Funciona bien tanto en datos conocidos como en datos completamente nuevos.

Generalizacion baja (overfitting): el modelo memorizo el ruido. Desempeno excelente en entrenamiento, desastroso en produccion.

La trampa del RMSE en entrenamiento

RMSE TrainRMSE TestDiagnostico
1.8 9.5 Sobreajuste severo — no generaliza
3.1 3.4 Buen ajuste — generaliza correctamente
9.1 9.8 Subajuste — modelo demasiado simple

Señal clave: si RMSE train es mucho menor que RMSE test, el modelo no generaliza (overfitting).

Error en funcion de la complejidad

Error en Train (decrece con la complejidad)
Error en Test (tiene un minimo optimo)
Punto optimo de complejidad

Trade-off sesgo-varianza: poca complejidad produce alto sesgo (underfitting). Demasiada complejidad produce alta varianza (overfitting). El conjunto de test es el unico instrumento que revela donde esta el equilibrio.

06 — Implementacion

Como hacerlo en Python

La implementacion tecnica es directa. Lo critico es comprender el orden correcto de las operaciones y los errores que invalidan la evaluacion.

Codigo con scikit-learn

# 1. Importar
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LinearRegression

# 2. Dividir — ANTES de cualquier ajuste
X_train, X_test, y_train, y_test = train_test_split(
    X, y,
    test_size=0.20,  # 20% para test
    random_state=42 # semilla fija
)

# 3. Entrenar SOLO con train
modelo = LinearRegression()
modelo.fit(X_train, y_train)

# 4. Evaluar SOLO con test
y_pred = modelo.predict(X_test)
rmse_test = np.sqrt(mean_squared_error(y_test, y_pred))
print(f"RMSE en TEST: {rmse_test:.4f}")

random_state = 42 garantiza que siempre obtengas la misma division. Es fundamental para la reproducibilidad del analisis.

Errores comunes que invalidan la evaluacion

ErrorConsecuencia
Escalar antes de dividirFuga de datos. La media y desviacion del test contaminan el escalado del train.
Usar test para seleccionar variablesEl test pierde independencia. Las metricas son optimistas por construccion.
No fijar random_stateResultados irreproducibles. El RMSE cambia en cada ejecucion del codigo.
No estratificar en clasificacionClases desbalanceadas en train o test. Modelo y evaluacion sesgados.
Mirar el test multiples vecesEl test se convierte en un tercer conjunto de entrenamiento implicitamente.

El orden correcto de operaciones

1. Dividir train / test
2. Escalar usando solo train → aplicar a test
3. Ajustar modelo en train
4. Evaluar una sola vez en test
5. Reportar
07 — Resumen

Las cinco razones fundamentales

Por que dividir los datos en train y test no es una convencion opcional — es la base de cualquier evaluacion estadistica honesta y reproducible.

I

Estimar el error real

El error en datos de entrenamiento subestima sistematicamente el error real. El test provee una estimacion insesgada del desempeno sobre datos nuevos.

II

Detectar sobreajuste

Si RMSE train es mucho menor que RMSE test, el modelo esta sobreajustado. Sin un conjunto de test, este problema es completamente invisible.

III

Comparar modelos honestamente

Un conjunto de test fijo e intocable es el unico terreno neutral para comparar dos modelos o dos especificaciones distintas.

IV

Simular el entorno real

El test replica lo que ocurrira cuando el modelo reciba datos reales que nunca ha visto. Es el ensayo antes del despliegue en produccion.

V

Reproducibilidad cientifica

Fijar la semilla aleatoria permite que otros investigadores reproduzcan exactamente los mismos resultados con el mismo conjunto de datos.

Estructura del split

Dataset completo — n observaciones
Train (70–90%)
— Ajustar coeficientes
— Seleccion de variables
— Ajuste de hiperparametros (via CV)
Test (10–30%)
— Evaluacion final, una sola vez
— Reporte de metricas
— Intocable hasta el final

Regla practica: nunca uses los datos de test mas de una vez. Cada vez que ajustas algo despues de mirar el test, lo estas convirtiendo implicitamente en otro conjunto de entrenamiento.
